# SSM Diagram Plugin

> Плагин для IntelliJ IDEA, который визуализирует конфигурации **Spring
> Statemachine** прямо внутри IDE.

SSM Diagram Plugin анализирует Java-конфигурацию Spring Statemachine
через IntelliJ PSI и строит интерактивную схему состояний, переходов,
событий, guards, actions и choice-ветвлений.

Основная цель плагина --- **сделать большие StateMachine-конфигурации
понятнее, нагляднее и удобнее для навигации, не выходя из IntelliJ
IDEA.**

------------------------------------------------------------------------

## Зачем нужен плагин?

По мере роста Spring Statemachine становится всё сложнее понимать полный
сценарий работы машины состояний непосредственно из Java-кода.

Конфигурация может содержать:

-   десятки состояний;
-   переходы между состояниями;
-   события;
-   guards --- условия выполнения переходов;
-   один или несколько actions;
-   choice-состояния;
-   ветки `first / then / last`;
-   initial и end states.

Плагин преобразует такую конфигурацию в наглядный граф прямо внутри
IntelliJ IDEA.

``` text
Java-конфигурация Spring Statemachine
                  │
                  ▼
          SSM Diagram Plugin
                  │
       ┌──────────┼──────────┐
       ▼          ▼          ▼
   Состояния   Переходы    Choices
                  │
           Events / Guards
                  │
               Actions
                  ▼
        Интерактивная схема
```

Для работы не требуется внешний сайт, Graphviz или запуск
Spring-приложения.

## Возможности

### Автоматический поиск конфигураций

Плагин ищет в текущем проекте конфигурации Spring Statemachine и
показывает найденные варианты в Tool Window **SSM Diagram**.

### Генерация диаграммы

На схеме могут отображаться:

-   состояния;
-   начальное состояние;
-   явно заданные конечные состояния;
-   переходы;
-   events;
-   guards;
-   actions;
-   choice-состояния;
-   choice-ветки;
-   ветки `otherwise`.

### Отображение Choice

Условные ветвления `.first(...)`, `.then(...)` и `.last(...)`
отображаются как отдельные ветки схемы. Это позволяет увидеть логику
выбора без необходимости вручную разбирать fluent-конфигурацию Java.

### Actions

Actions перехода отображаются отдельно рядом с целевой частью перехода.

Если у перехода несколько actions, они показываются отдельными строками,
а не объединяются в одну длинную подпись.

Error actions сохраняются во внутренней семантической модели, но пока
намеренно не выводятся на основной диаграмме, чтобы не перегружать её.

### Навигация в исходный код

Если PSI позволяет определить исходный элемент, из диаграммы можно
перейти обратно в код для:

-   states;
-   events;
-   guards;
-   actions.

Таким образом, диаграмма работает не только как визуальная документация,
но и как дополнительный способ навигации по реализации StateMachine.

### Преобразование графа для читаемости

Настоящие StateMachine-графы не всегда удобно отображать буквально.

Если в одно состояние приходит большое количество переходов, плагин
может создать несколько **визуальных копий** одного логического
состояния:

``` text
        A                 B                 C
        │                 │                 │
        ▼                 ▼                 ▼
   ┌─────────┐       ┌─────────┐       ┌─────────┐
   │  READY  │       │  READY  │       │  READY  │
   └─────────┘       └─────────┘       └─────────┘
        │                 │                 │
        └──────── logicalId = READY ────────┘
```

Это не разные Spring states. Все такие блоки представляют одно и то же
логическое состояние.

Такое преобразование влияет только на визуализацию и **не изменяет
семантику Spring Statemachine**.

### Иерархическая раскладка

Текущий layout engine располагает узлы сверху вниз.

Процесс включает:

1.  вычисление уровней графа;
2.  упорядочивание узлов внутри уровней;
3.  вычисление координат;
4.  ортогональную маршрутизацию стрелок;
5.  разделение параллельных переходов;
6.  позиционирование подписей.

### Масштабирование и управление областью просмотра

В Tool Window доступны:

-   уменьшение масштаба;
-   отображение текущего масштаба и возврат к 100%;
-   увеличение масштаба;
-   **Fit**;
-   **Center**;
-   масштабирование через `Ctrl` / `Cmd` + колесо мыши.

### Generate, Refresh и Clear

-   **Generate** --- анализирует выбранную в списке конфигурацию и
    строит диаграмму.
-   **Refresh** --- повторно анализирует конфигурацию, которая сейчас
    отображается.
-   **Clear** --- очищает текущую диаграмму, не сбрасывая выбранную
    конфигурацию.

### Генерация из Project View

Диаграмму можно построить непосредственно из дерева проекта:

**ПКМ по Java-конфигурации → Generate SSM Diagram**

### Фоновый PSI-анализ

Поиск конфигураций и генерация диаграммы могут обращаться к PSI, resolve
и индексам IntelliJ.

Потенциально тяжёлые операции выполняются через non-blocking read
actions в smart mode, а не непосредственно в Swing EDT.

Во время выполнения Tool Window может показывать состояние:

``` text
◌ Searching configurations...
◌ Generating diagram...
◌ Refreshing diagram...
```

# Как это работает

## Общая архитектура

Плагин разделяет анализ семантики Spring Statemachine и её визуальное
представление.

``` text
                    Java source
                        │
                        ▼
              ┌───────────────────┐
              │ SSM Config Finder │
              └─────────┬─────────┘
                        │
                        ▼
              ┌───────────────────┐
              │   PSI Analyzer    │
              └─────────┬─────────┘
                        │
          ┌─────────────┼─────────────┐
          ▼             ▼             ▼
       States      Transitions      Choices
                        │
                        ▼
              ┌───────────────────┐
              │ StateMachineModel │
              └─────────┬─────────┘
                        │
                        ▼
              ┌───────────────────┐
              │DiagramGraphBuilder│
              └─────────┬─────────┘
                        │
                        ▼
              Canonical DiagramGraph
                        │
                        ▼
           ┌─────────────────────────┐
           │ReadableGraphTransformer │
           └────────────┬────────────┘
                        │
                        ▼
               Visual DiagramGraph
                        │
                        ▼
           ┌─────────────────────────┐
           │HierarchicalLayoutEngine │
           └────────────┬────────────┘
                        │
                        ▼
           ┌─────────────────────────┐
           │ OrthogonalEdgeRouter    │
           └────────────┬────────────┘
                        │
                        ▼
                 DiagramLayout
                        │
                        ▼
                 Swing Renderer
                        │
                        ▼
              IntelliJ Tool Window
```

## 1. Поиск конфигураций

Плагин использует модель проекта IntelliJ, PSI и индексы наследования
для поиска поддерживаемых конфигураций Spring Statemachine на основе:

``` java
EnumStateMachineConfigurerAdapter
```

Spring-приложение при этом запускать не требуется, Application Context
не создаётся.

## 2. PSI-анализ

Java-код анализируется через **IntelliJ PSI (Program Structure
Interface)**.

Это принципиальное решение архитектуры: вместо разбора исходного текста
через регулярные выражения плагин работает со структурой Java-кода и
ссылками, которые понимает сама IntelliJ IDEA.

Анализатор извлекает примерно такую структуру:

``` text
StateMachine
├── states
├── initial state
├── end states
├── transitions
│   ├── source
│   ├── target
│   ├── event
│   ├── guard
│   └── actions
└── choices
    ├── source
    ├── first
    ├── then
    └── last
```

Expression resolver поддерживает распространённые способы задания
значений, включая enum constants, локальные переменные, параметры циклов
и конструкции `List.of(...)`.

## 3. Семантическая модель

Результатом PSI-анализа является нормализованный `StateMachineModel`.

``` text
StateMachineModel
│
├── SsmState
│
├── SsmTransition
│   ├── source
│   ├── target
│   ├── event
│   ├── guard
│   └── List<SsmAction>
│
└── SsmChoice
    └── branches
```

Эта модель описывает смысл Spring-конфигурации и не содержит информации
о том, где блок должен находиться на экране.

## 4. Канонический граф

`DiagramGraphBuilder` преобразует `StateMachineModel` в канонический
граф.

На этом этапе действует принцип:

``` text
одно логическое состояние = один узел графа
```

Builder также создаёт визуальные маркеры initial state и явно заданных
Spring end states.

## 5. Преобразование для читаемости

`ReadableGraphTransformer` может преобразовать канонический граф в более
удобный для отображения вариант.

Визуальные копии состояния сохраняют один `logicalId`, поэтому
логическая и визуальная идентичность остаются разделены.

## 6. Hierarchical Layout

`HierarchicalLayoutEngine` располагает граф примерно следующим образом:

``` text
Level 0                 INITIAL
                           │
Level 1                 CREATED
                           │
                ┌──────────┴──────────┐
                ▼                     ▼
Level 2      PROCESSING             FAILED
                │
                ▼
Level 3       FINISHED
```

Сначала вычисляются окончательные позиции узлов, и только после этого
начинается маршрутизация переходов.

## 7. Маршрутизация переходов

`OrthogonalEdgeRouter` строит маршруты между узлами и определяет позиции
подписей.

Концептуально переход выглядит так:

``` text
       EVENT
         ↓
      [GUARD]
         ↓
 ┌──────────────┐
 │ TARGET STATE │
 └──────────────┘
         ↓
   ⚡ firstAction
   ⚡ secondAction
```

Если между одной парой состояний существует несколько переходов, им
назначаются отдельные offsets, чтобы линии не накладывались полностью
друг на друга.

## 8. Рендеринг и взаимодействие

Renderer получает уже подготовленную геометрию графа.

Его зона ответственности:

``` text
PSI-анализ             ❌
семантика графа        ❌
расчёт layout          ❌

отрисовка              ✅
hit areas              ✅
hover                  ✅
навигация              ✅
```

Сначала рисуются переходы, затем узлы. Подписи имеют непрозрачный фон,
чтобы линии не ухудшали читаемость текста.

# Модель потоков

IntelliJ PSI и индексы имеют строгие требования к потокам.

Потенциально тяжёлые операции, такие как:

-   поиск наследников;
-   reference resolution;
-   PSI-анализ;
-   обращение к индексам;

не должны блокировать Swing Event Dispatch Thread.

Архитектура выполнения:

``` text
                  EDT / Swing
                      │
            пользователь нажал Generate
                      │
                      ▼
          Non-blocking Read Action
                      │
                 Smart Mode
                      │
          ┌───────────┼───────────┐
          ▼           ▼           ▼
         PSI       indexes      resolve
          └───────────┼───────────┘
                      │
                      ▼
             StateMachineModel
                      │
                      ▼
                  EDT / Swing
                      │
                      ▼
               показ диаграммы
```

Это позволяет не блокировать интерфейс IntelliJ во время анализа
конфигурации.

# Сборка из исходников

## 1. Клонирование репозитория

``` bash
git clone <repository-url>
cd ssm-diagram-plugin
```

Замените `<repository-url>` на URL репозитория.

## 2. Сборка плагина

macOS / Linux:

``` bash
./gradlew clean buildPlugin
```

``` powershell
gradlew.bat clean buildPlugin
```

Готовый ZIP создаётся в:

``` text
build/distributions/
```

Например:

``` text
build/distributions/ssm-diagram-plugin-1.0-SNAPSHOT.zip
```

# Установка

## Установка готового ZIP

1.  Откройте **IntelliJ IDEA**.
2.  Перейдите в **Settings / Preferences**.
3.  Откройте раздел **Plugins**.
4.  Нажмите **⚙️**.
5.  Выберите **Install Plugin from Disk...**.
6.  Выберите ZIP из `build/distributions`.
7.  Подтвердите установку.
8.  Перезапустите IntelliJ IDEA, если она это предложит.

ZIP выбирается напрямую --- распаковывать его не нужно.

# Использование

## Через Tool Window

Откройте:

**View → Tool Windows → SSM Diagram**

либо воспользуйтесь кнопкой **SSM Diagram** на боковой панели IntelliJ
IDEA.

После поиска доступных конфигураций выберите нужную и нажмите
**Generate**.

## Refresh

После изменения Java-конфигурации StateMachine нажмите **Refresh**.

Плагин повторно проанализирует именно ту конфигурацию, которая сейчас
отображается на диаграмме.

## Clear

Нажмите **Clear**, чтобы убрать текущую диаграмму. Выбор конфигурации
при этом сохраняется.

## Генерация из Java-файла

1.  Найдите Java-конфигурацию StateMachine в Project View.
2.  Нажмите по файлу правой кнопкой мыши.
3.  Выберите **Generate SSM Diagram**.
4.  Откроется Tool Window с построенной диаграммой.

# Семантика диаграммы

Плагин принципиально разделяет несколько уровней:

``` text
Spring semantics
      │
      ▼
StateMachineModel
      │
      ▼
Canonical DiagramGraph
      │
      ▼
Visual DiagramGraph
      │
      ▼
Rendered diagram
```

Благодаря этому визуальные улучшения не изменяют смысл StateMachine.

Например, создание нескольких визуальных копий одного состояния не
создаёт дополнительные состояния в `StateMachineModel`.

# Принципы разработки

### Сохранять семантику Spring

Визуализация не должна изменять смысл, извлечённый из исходной
конфигурации.

### PSI вместо разбора текста

Java-конфигурация анализируется через программную модель IntelliJ, а не
через зависящие от форматирования регулярные выражения.

### Renderer занимается только отображением

Парсинг, семантический анализ, преобразование графа и layout должны
находиться за пределами renderer.

### Читаемость важнее буквальной геометрии

Задача диаграммы --- объяснить StateMachine разработчику, а не просто
буквально соединить все состояния линиями.

### Работа внутри IntelliJ IDEA

Основной сценарий не должен требовать копирования сгенерированного
описания на внешний сайт или запуска отдельного сервиса визуализации.

------------------------------------------------------------------------

# Текущие ограничения

Плагин находится в активной разработке.

Spring Statemachine позволяет описывать конфигурации множеством
способов. Текущий анализатор ориентирован на Java-конфигурации, которые
можно статически разрешить через IntelliJ PSI и поддерживаемые
expression patterns.

Сильно динамические конфигурации могут потребовать дополнительной
поддержки анализатора.

Layout engine ориентирован прежде всего на читаемость и в дальнейшем
может улучшаться для очень больших, плотных или циклических графов.

------------------------------------------------------------------------

# Возможные направления развития

В дальнейшем можно добавить:

-   улучшенную работу с очень большими графами;
-   дальнейшую оптимизацию layout;
-   улучшенное отображение циклов и обратных переходов;

-   экспорт диаграммы;
-   поддержку дополнительных вариантов конфигурации Spring Statemachine.

``` text
Renderer
```

Если новая функциональность меняет только внешний вид диаграммы, её
обычно следует реализовывать **после** `StateMachineModel`.

Если функциональность меняет то, что плагин понимает из
Spring-конфигурации, она относится к analyzer/model layer.
